# Debouncing in React

Firing an API call on every single keystroke is a fast way to kill server performance and frustrate users with laggy results. If you've seen your network tab explode while typing in a search bar, you know the problem.

Debouncing is the solution. It’s a simple technique that delays execution until a user stops interacting for a set period.

Think of it like an elevator door. It doesn't close the second someone steps in; it waits a beat to see if anyone else is coming.

---

## The Problem: Event Overload

```jsx
function SearchBar() {
  const handleChange = (e) => {
    fetchResults(e.target.value);
  };

  return <input onChange={handleChange} placeholder="Search..." />;
}
```

If a user types "react hooks", that’s 11 characters and 11 API calls. Most of them are useless intermediate states ("r", "re", "rea"). 

---

## The Solution: A Reusable `useDebounce` Hook

The most efficient way to handle this in React is a custom hook. It keeps your components clean and logic portable.

```ts
import { useState, useEffect } from "react";

function useDebounce<T>(value: T, delay: number = 500): T {
  const [debouncedValue, setDebouncedValue] = useState<T>(value);

  useEffect(() => {
    const timer = setTimeout(() => {
      setDebouncedValue(value);
    }, delay);

    return () => clearTimeout(timer);
  }, [value, delay]);

  return debouncedValue;
}

export default useDebounce;
```

The logic is straightforward: every time the input `value` changes, we reset a timer. The `debouncedValue` only updates if that timer actually finishes without being interrupted by another keystroke.

---

## Implementing the Search Bar

Now, your component only cares about the "final" value after the user pauses.

```tsx
import { useState, useEffect } from "react";
import useDebounce from "../hooks/useDebounce";

function SearchBar() {
  const [query, setQuery] = useState("");
  const debouncedQuery = useDebounce(query, 400);

  useEffect(() => {
    if (!debouncedQuery) return;
    fetchResults(debouncedQuery);
  }, [debouncedQuery]);

  return (
    <input
      value={query}
      onChange={(e) => setQuery(e.target.value)}
      placeholder="Search..."
    />
  );
}
```

The UI stays responsive because `query` updates instantly, but the expensive `fetchResults` only runs when the user stops for 400ms.

## Debouncing Callbacks (Auto-save)

Sometimes you don't want to debounce a state value, but the function execution itself — like an auto-save feature in an editor.

```tsx
import { useCallback, useRef } from "react";

function useDebouncedCallback<T extends (...args: any[]) => void>(
  fn: T,
  delay: number
): T {
  const timerRef = useRef<ReturnType<typeof setTimeout> | null>(null);

  return useCallback(
    (...args: Parameters<T>) => {
      if (timerRef.current) clearTimeout(timerRef.current);
      timerRef.current = setTimeout(() => fn(...args), delay);
    },
    [fn, delay]
  ) as T;
}
```

```tsx
function NoteEditor() {
  const saveNote = useDebouncedCallback((content: string) => {
    api.save({ content });
  }, 600);

  return (
    <textarea
      onChange={(e) => saveNote(e.target.value)}
      placeholder="Start writing..."
    />
  );
}
```

## When to use Lodash?

Don't reinvent the wheel if you're already using a utility library. `lodash/debounce` is battle-tested. Just remember to wrap it in `useMemo` so you don't recreate the function on every render.

```tsx
import { useMemo, useEffect } from "react";
import debounce from "lodash/debounce";

function SearchBar() {
  const handleSearch = useMemo(
    () =>
      debounce((value: string) => {
        fetchResults(value);
      }, 400),
    []
  );

  useEffect(() => {
    return () => handleSearch.cancel();
  }, [handleSearch]);

  return <input onChange={(e) => handleSearch(e.target.value)} />;
}
```

**Pro tip:** Always cancel the debounce on unmount to prevent memory leaks or state updates on components that no longer exist.

## The "Silent" Killers

**1. Missing Cleanup**
If you don't clear your timeouts, you'll eventually run into "stale" state updates on unmounted components. React will warn you, but your app will already be behaving unpredictably.

**2. The Stable Reference Trap**
If you define a debounced function inside a component without `useMemo`, a new timer starts on every render. Your debounce will basically never fire because it keeps getting reset.

**3. Debouncing vs. Throttling**
They aren't interchangeable. 
- **Debounce:** "Wait until I'm done." (Search, Auto-save)
- **Throttle:** "Give me updates every X ms." (Scrolling, Drag-and-drop)

---

Debouncing is a small change that yields massive performance gains. Use a hook for simple state-based logic, and reaching for Lodash when you need cancellation or complex timing.

Your servers (and your users) will definitely see the difference.
